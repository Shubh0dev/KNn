# KASHINAGRI — PART 1: BUILD THE SAME PREMIUM HOMEPAGE

Act as a senior product designer and full-stack frontend engineer. Build a polished, responsive Next.js website called **KashiNagri — Your Complete Guide to Kashi**.

This is the first part of a larger four-part build. We will implement the homepage now and expand the website in later tasks. Do not attempt to build a complete backend or booking marketplace in this phase.

I am also building the same website in Antigravity. Follow the same product requirements and visual direction described below so that both implementations can be compared fairly.

## PRODUCT AND VISUAL REFERENCES

KashiNagri is a destination discovery and travel-planning website for Varanasi, India.

Use my two supplied screenshots as visual references:
- Screenshot 1 shows the desired homepage breadth, large Varanasi hero, search bar, shortcut categories, stays, food, spiritual services, neighbourhoods, itineraries and travel categories.
- Screenshot 2 shows the desired accommodation page style, including a panoramic hero, budget categories, room types, location shortcuts and listing cards. The dedicated accommodation page will be implemented in a later part.

Create an original, premium design inspired by these references.

Brand identity:
- Name: KashiNagri
- Tagline: Your Complete Guide to Kashi
- Warm ivory backgrounds
- Deep maroon primary actions
- Saffron and muted gold accents
- Elegant serif headlines
- Clean sans-serif interface text
- Authentic Varanasi photography
- Subtle borders, restrained shadows and clear spacing
- A culturally rich but modern visual identity

Avoid a generic SaaS dashboard appearance, excessive bright colours, cramped cards and irrelevant imagery.

## TECH STACK

Use:
- Next.js App Router
- React
- TypeScript
- Tailwind CSS
- Lucide icons
- Reusable, typed components
- Dedicated mock-data modules

Respect the existing workspace if one already exists. Inspect its structure and scripts before making changes. Keep dependencies lean and ensure the project remains runnable.

## HEADER

Build a responsive desktop header with:
- KashiNagri logo/temple emblem
- Global search
- Explore on Map
- Hindi/English selector UI
- Login/Register entry point
- A second navigation row containing Home, Temples & Darshan, Ghats & Ganga, Stay in Kashi, Food & Dining, Travel, Shopping, Spiritual Services, Guides, Events and More

Add functional dropdowns where appropriate. On mobile, use a compact header and an accessible menu/drawer.

## HERO

Create a cinematic Varanasi riverfront hero with an image overlay, large headline “Experience the Divine Kashi”, a concise subtitle, a search field, search button and quick-search chips for Hotels, Rooms under ₹500, Famous Food, Kashi Guide and Banarasi Saree.

Use suitable image assets and graceful fallbacks. Text must remain readable on every viewport.

## REQUIRED HOMEPAGE SECTIONS

Implement all of these:

1. Category shortcuts: temples, ghats, stays, food, transport, spiritual services, guides, shopping, local directory, trip planner, events and more.
2. Stay in Kashi: budget rooms, standard hotels, premium hotels, luxury hotels, dharamshalas, guest houses, PG/hostels, rentals and homestays.
3. Food & Dining: street food, restaurants, thali, sweets/snacks and cafes.
4. Spiritual Services: puja/path, jyotish/kundli, pandit/purohit and other service categories.
5. Explore Kashi by Area: Vishwanath Gali, Godowlia, Assi Ghat, Lanka/BHU, Cantt/station area and Ravindrapuri.
6. Plan Your Kashi Trip: one-day, two-day, three-day and budget itineraries.
7. Guides & Experiences: temple guides, ghat guides, food walks and boat rides.
8. Shopping in Kashi: Banarasi sarees, handicrafts, puja items and souvenirs.
9. Travel & Transport: airport transfers, railway information, local transport and boat travel.
10. Events & Festivals: Dev Deepawali, Mahashivratri, Ganga Aarti and upcoming events.
11. Trust section: verified information, local insights, easy planning and all-in-one discovery.
12. Local business CTA: List Your Business and Partner with KashiNagri.
13. Footer with About, categories, guides, contact, privacy, terms, disclosures and social links.

Use consistent section headings, attractive image cards, short supporting text and clear View All actions. The homepage must feel complete, not like a wireframe.

## MY KASHI TRIP

Make My Kashi Trip easy to discover through the navigation and homepage. Its primary CTA must open `/plan-my-trip`.

In this part, create a preview section and navigation entry point only. The complete itinerary builder will be developed in Part 3.

## FUNCTIONALITY

Build a working frontend, not a static mockup:
- Working internal navigation
- Functional dropdowns and mobile menu
- Search input and submission
- Search against available mock data where practical
- Working category and View All links
- Explore on Map entry point
- My Kashi Trip entry point
- Responsive layouts
- Empty search-results state
- Accessible buttons, keyboard focus and appropriate interaction states

Do not leave dead buttons or `href="#"` placeholders.

Use realistic mock content, but clearly avoid presenting fictional listings, prices, ratings or inventory as verified real-world information. Do not implement fake bookings, fake authentication or payment flows.

## ARCHITECTURE

Organize the code into reusable components for the header, hero, category strip, section headings, image cards, listing grids and footer.

Keep mock data and types separate from the UI. Suggested routes:
- `/`
- `/explore`
- `/plan-my-trip`

The root URL `/` must show the actual homepage.

## RESPONSIVENESS AND POLISH

Optimize for:
- Desktop widths around 1440px
- Tablet widths around 768px
- Mobile widths around 375–430px

Use responsive grids, sensible image cropping, consistent card dimensions, readable typography, good contrast and adequate touch targets.

Avoid horizontal overflow, broken images, hydration errors, unnecessary animation and console errors.

## DEFINITION OF DONE

The homepage must contain every specified section, use the supplied references for visual direction, have working interactions and responsive layouts, and run successfully.

Inspect the project first. Then implement the actual frontend, run the available checks and fix errors. Do not stop at a plan or mockup.

At completion, report:
- Implemented sections and routes
- Functional interactions
- Any remaining limitations
- Commands to run the website

Keep the architecture ready for Parts 2, 3 and 4 without overengineering the first phase.
